# ADR-004: Phase 5 getters, quick load, and the 0.1 book

* Status: Accepted
* Date: 2026-11-22
* Phase: P5 (libraries, quick load, 0.1 book)
* Design plan: [`docs/design-plan.md`](../design-plan.md) (§6.13, §13, §14, §16, §17, §18)

## Context

P5 is the last 0.1 phase: a library crate publishes a section and a getter, an
application mounts that section (more than once, under different keys), `quick::load`
runs the twelve-factor pipeline without a hand-written context, and the book documents
that surface. The design plan's `ProjectSection<Path!(config.http)>` does not match
`cgp-fork` 1.1: `Path!` rejects a path that does not start with `@`, and `#[cgp_getter]`
implements the provider only for `UseField` and `WithProvider<FieldGetter>`. The plan's
builder example `env_prefix("X_")` also disagrees with §6.2, which stores the prefix
without a trailing separator.

## Decision

1. **Public projection is `WithProvider<ProjectSection<Path!(@config.http)>>`.**
   `ProjectSection` lives in `cgp-config-core` and implements `FieldGetter` by walking
   `PathCons` through `MapField`. `ProjectSection<Nil>` returns the context. The request
   context holds `Arc<AppConfig>` or `&AppConfig` and derives `HasField`. The getter
   borrows from that value. It does not borrow through `ArcSwap`. `ConfigHandle` stays
   0.2.
2. **`#[config(getter)]` emits the trait.** The name drops a trailing `Config` when the
   remainder is non-empty and starts with an ASCII uppercase letter. `HttpConfig` and
   `Http` both emit `HasHttpConfig`, method `http_config`, component
   `HttpConfigGetterComponent` (generated by `#[cgp_getter]` in the library's module).
   The application imports that component. A library that derives a getter depends on
   `cgp-fork` directly, because the macro expands to `::cgp_fork`.
3. **A mounted section is `#[config(nested, mount = "http")]`.** `nested` is what the
   schema walks. `mount` is the document key and the env segment when it differs from
   the serde key. The same section type may be mounted twice. Two fields whose resolved
   mount is equal are a compile error (`doc_key` uniqueness). Duplicate `env_raw` is
   already a compile error. A field key `port` and `env = "PORT"` on another field of
   the same section collide, because env segments fold case.
4. **`#[config(partial)]` emits `{Name}Partial`.** Configurable fields become
   `Option<T>` (an existing `Option<T>` is not wrapped again). `FinalizeOptionalAll`
   fills const defaults and reports every still-missing required field. `#[serde(skip)]`
   fields are `Default` on the real struct, omitted from the partial, and omitted from
   `ConfigMeta`. A partial with at least one configurable field derives `CgpData`.
5. **`quick::load` is the process entry. `quick::load_from` is the hermetic one.**
   `load` captures the process environment and searches the real filesystem.
   `load_from` takes an `EnvSnapshot` and a file map, rooted at `/cgp-config-quick`,
   and reads through `ReadFromMap`. Doctests call `load_from`. The context behind
   `load_from` is `#[doc(hidden)]` so the public bound can name it; callers do not
   construct it.
6. **`StdLoader::builder()` stores the prefix without a trailing separator.** `APP` is
   accepted. `APP_` and `APP__` and an empty prefix are rejected. The builder does not
   capture the process environment unless `capture_env()` is called. `env(snapshot)`
   supplies a snapshot and clears capture.
7. **The semver baseline is `origin/main`.** `cargo xtask semver` checks against
   `SEMVER_BASELINE` (default `origin/main`) and stays advisory until 0.1.0. This alpha
   does not add a tag. The book in `book/` documents the P1–P5 surface, including one
   page per `ConfigError::code()`. `cargo xtask book` runs `mdbook` and is not part of
   `cargo xtask ci`.

## Consequences

* The design plan's §6.13 example, §13 builder, and §17 docs paragraph match this
  record. `Path!(config.http)` without `@`, and a getter provider that is not
  `WithProvider`, do not compile against `cgp-fork` 1.1.
* `examples/multi-crate-workspace` is the acceptance crate: the libraries build with
  `default-features = false, features = ["derive"]` and are `#![no_std]`; the app wires
  two sections and loads them with `load_from`.
* A hand-written `ConfigSection` used with `quick::load` / `load_from` also implements
  `ValidateSections` and `Deserialize`, the same bounds `StdLoader::load` already
  requires through `CanLoadConfig`.
